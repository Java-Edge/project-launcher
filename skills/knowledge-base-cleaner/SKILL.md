# 知识库冗余清理（Knowledge Base Cleaner）

当用户说"清理知识库""删除重复内容""减少 token 浪费"时，按此流程执行。

## 核心原则

1. **先分析，后删除** — 必须先生成分析报告，用户确认后才执行删除
2. **保守策略** — 只删确定无价值的重复，保留任何可能有知识价值的内容
3. **备份优先** — 删除前自动创建 `.kb-cleaner-backup/` 目录存放待删文件

## 工作流（必须按顺序）

### 1. 扫描与分类

遍历目标目录所有 `.md` 文件，按以下类别统计：

| 类别 | 识别特征 | 风险等级 |
|------|---------|---------|
| 备份目录重复 | 路径含 `backup/`、`.bak`、`old/` 等，且正式目录有同名文件 | 低 |
| 本地图片路径 | `![](/Users/...)` 或 `![](C:\...)` 等绝对路径 | 低 |
| 网页导航残留 | `Connect these docs to Claude`、`Was this page helpful?`、`Yes/No` 等 | 低 |
| 代码模板重复 | 跨文件重复 ≥3 次的代码块（如 `if __name__ == "__main__"`） | 中 |
| 同名文件跨目录 | 不同目录下同名文件，需 diff 确认 | 中 |
| 宣传套话 | "加速""赋能""最佳实践""业界领先"等高频词 | 高（需改写，非删除） |

### 2. 生成分析报告

输出格式：

```
## 知识库清理分析报告

### 统计概览
- 总文件数：N
- 可安全删除：X 文件 / Y 行 / ~Z token
- 需人工确认：A 文件
- 建议改写：B 处

### 分类明细
[每类列出具体文件路径、重复次数、估算 token]

### 建议执行顺序
1. P0：删除备份目录重复（零风险）
2. P1：清理本地图片路径 + 网页导航残留
3. P2：合并代码模板重复
4. P3：改写宣传套话（非删除）
```

### 3. 用户确认后执行

**P0 - 备份目录删除：**
- 先 diff 确认备份与正式文件 100% 相同
- 移动备份到 `.kb-cleaner-backup/` 而非直接删除
- 记录删除日志

**P1 - 图片路径清理：**
- 正则替换 `![](/Users/...)` → `![示意图]`
- 保留 alt 文本，删除不可访问的绝对路径

**P1 - 网页导航清理：**
- 识别页眉页脚边界（通常 20-30 行）
- 删除包含导航关键词的行
- 保留实质内容

**P2 - 代码模板合并：**
- 标记重复 ≥3 次的代码块
- 建议保留 1 处完整示例，其余改为 `参见 XX 章节`
- **不自动修改**，只生成建议清单

### 4. 验证与报告

执行后验证：
- 被删文件数与计划一致
- 正式目录文件未受影响
- 生成最终清理报告

## 安全边界（务必遵守）

- **绝不直接 `rm -rf`** — 必须移到 `.kb-cleaner-backup/`，保留 7 天后再彻底删除
- **diff 确认** — 备份目录文件必须与正式目录 100% 相同才标记为可删
- **用户确认** — 任何删除操作前必须展示完整清单并获得明确同意
- **保留唯一副本** — 如果备份目录有全库唯一的文件，必须提示用户选择迁移或保留

## 输出产物

执行完成后生成：
1. `kb-cleanup-report.md` — 详细清理报告
2. `.kb-cleaner-backup/` — 被删文件备份（7 天后可删）
3. `kb-cleanup-log.json` — 操作日志（时间、文件、原因）

## 示例对话

用户："帮我清理一下知识库里的重复内容"

Agent：
1. 扫描目录，发现 800 个 md 文件
2. 识别出：备份目录重复 7 文件、图片路径 175 行、导航残留 9 文件
3. 生成报告："可安全删除约 63,000 token，详见分类明细..."
4. 用户确认后执行 P0+P1
5. 输出："已清理 182 处冗余，备份在 .kb-cleaner-backup/，报告已生成"
